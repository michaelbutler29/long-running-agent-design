# Skill Validation Checklist

Before publishing a new or revised skill, confirm structural completeness.

## Criteria

- [ ] **Contextual** — the procedure references system-specific tools or workflows not derivable from training data.
- [ ] **Concrete** — steps name specific tool calls and parameters. No ambiguous instructions.
- [ ] **Complete** — procedure, failure modes, and activation conditions are present.
- [ ] **Current** — you have read the existing skill text (if modifying) and are revising from the actual content, not from memory.
- [ ] **Committed** — a written rationale accompanies the revision: what changed, why, and what experience led here.

## If any criterion is not met

Do not publish. Address the shortfall first:

| Shortfall | Action |
|---|---|
| Not contextual | Reconsider — this may belong as a prompt amendment or may not be needed at all. |
| Not concrete | Add specific tool names and parameters to each step. |
| Incomplete | Fill in missing sections. |
| Not current | Read the current skill text before revising. |
| No rationale | Write the commit rationale before publishing. |
